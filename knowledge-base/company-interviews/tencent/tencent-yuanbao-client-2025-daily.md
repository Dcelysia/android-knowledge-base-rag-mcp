## 三面

1. 自我介绍。
2. 介绍项目。
3. 日志记录哪些数据，关注哪些指标？
4. 是否有触达率等数据？
5. 如何判断用户下发消息到达，是否有回执？
6. 选择第三方 API 云厂商时考虑成本还是综合因素？
7. 接入了哪些厂商的服务？
8. 相同功能但调用接口不同，如何抹平 API 差异？
9. 为什么使用负载均衡，策略是什么，如何实现？
10. 项目的 Redis 内存优化如何做？
11. 数据结构发生了什么变化，如何设计？
12. 如何通过牺牲存储内容减少 Redis 内存占用，是否有过滤优先级？
13. 负载情况及指标大概是多少？
14. 这个服务具体是什么，挑战在哪里？
15. 消息队列如何实现，底层原理是什么？
16. Redis 如何保证一致性，线程模型是什么？
17. Redis 单线程如何在保证一致性的同时保证性能？
18. 什么是 IO 多路复用？
19. Java 的优缺点。
20. Java 因虚拟机编译导致执行效率慢，有哪些优化方式？
21. 为什么不提前把 Java 全部编译成静态机器码？
22. 如果提前编译，为什么会影响多态和反射？
23. 是否用 Java 调用过 C 等其他语言？
24. 经验更多偏后端，为什么考虑客户端？

1. 客户端的核心竞争力更偏业务提升还是技术提升？
2. 日常工作的中心是什么？
3. 多部门协作通常是什么模式？
